# MoveAWheel 통과 가능성 지도

LiDAR·IMU 실측 진동 지표를 카카오맵 경로 위에 표시하고, 별도의 시연 지도에서 휠체어 경로 선택을 살펴보는 웹사이트입니다.

**[사이트 열기](https://lightemittingdiode.github.io/MVW_site_passabilityMap/mvw-measured-map/)** · [월드 모델 기술 소개](https://lightemittingdiode.github.io/MVW_site_wheelchairWorldModel/)

## 화면 구성

| 탭 | 내용 | 데이터 성격 |
| --- | --- | --- |
| **Map** | 2026-10-16 LiDAR·IMU 측정값을 카카오맵 위의 지정 경로 구간에 표시합니다. 구간에 마우스를 올리거나 선택하면 점수, 측정 시각, IMU RMS와 매핑 정보를 봅니다. | 실측 기반 **잠정 진동 지표** |
| **Map_Demo** | 지도에서 출발·도착을 선택하고 최단·최적·안전 경로의 거리, 예상 시간, 평균·최대 위험도를 비교합니다. | 도로 선형은 카카오 도보 경로 또는 OSM 시연망, 노면·위험도는 시연 값 |
| **World Model** | 센서 입력부터 정적·동적 위험도, 통과 판정, 경로 탐색까지의 흐름을 설명합니다. | 기술 설명 |

**Map의 실측 점수와 Map_Demo의 시연 위험도는 서로 다른 데이터입니다.** 실측 점수가 검증된 휠체어 통행 가능 판정이나 사고 확률을 뜻하지는 않습니다.

## Map: 실측 데이터와 구간 정합

사용자가 확인한 `walkway_player/vibration_map`의 2026-10-16 측정 3개 세션을 사용했습니다. 원본 입력은 `trajectory.json`, `vibration.json`, `registration.json`입니다. 배포 사이트에는 처리된 결과인 [`mvw-measured-map/walking-matched-data.js`](mvw-measured-map/walking-matched-data.js)가 포함되어 있어 파일을 따로 올리지 않아도 지도가 나타납니다.

| 항목 | 수량 |
| --- | ---: |
| LiDAR 측정 프레임 | 25,387 |
| IMU 값과 대응된 프레임 | 24,818 |
| IMU 미대응 프레임 | 569 |
| 지도에 표시하는 지정 경로 구간 | 189 |
| 프레임을 직접 집계한 구간 | 174 |
| 주변 실측점 10개씩 연결한 구간 | 15 |

실측 궤적의 기준점과 북쪽 방향을 잠정 보정한 다음, **사용자가 지정한 경로의 카카오 도보 선형**을 약 5m 구간으로 나누어 측정점을 가장 가까운 구간에 할당했습니다. 차도 위 선형도 이번 지정 경로에 포함됩니다. 직접 대응 프레임이 없던 15개 구간은 가까운 실제 측정점 10개씩 연결하고, 상세 패널에 가장 가까운 거리와 최대 거리를 표시합니다. 직접 집계된 구간에서는 이 세 가지 출처 항목을 `-`로 표시합니다. 위치 정합과 실제로 걸은 보도의 일치 여부는 아직 현장 검증이 필요합니다.

### 점수 계산과 표시

원본 분석의 휴대폰 선형가속도 **2–8 Hz 대역, 중심 1초 RMS**를 사용합니다. 유효 프레임의 임시 점수는 다음과 같습니다.

```text
프레임 점수 = min(100, 프레임 RMS / 2.8799 m/s² × 100)
구간 점수 = 해당 구간에 할당된 유효 프레임 점수의 산술평균
```

`2.8799 m/s²`는 이 측정 데이터의 RMS 95백분위 값입니다. 지도 색상은 구간 점수의 0–100 연속 팔레트를 사용합니다. 상세 패널에는 프레임 점수의 최댓값, **IMU RMS 평균·최대**, 측정 시각, 표본 수와 매핑 거리를 함께 표시합니다. IMU 미대응은 0점으로 바꾸지 않습니다. 원본 파일의 해시와 시간 대응 정보는 결과 데이터의 `provenance`에 기록되어 있습니다.

측정 장치가 카메라 브리지에 부착되어 있어 보행 충격, 장착부 움직임, 시간·위치 정합 오차가 점수에 영향을 줄 수 있습니다. LiDAR Z가 평면화되어 있으므로 경사, 단차, 기하학적 노면 거칠기를 이 데이터로 계산하지 않았습니다. [`mvw-measured-map/MEASURED_DATA.md`](mvw-measured-map/MEASURED_DATA.md)는 **초기 분석 단계**를 기록하며 현재 배포 상태와 다른 부분이 있습니다.

## Map_Demo: 세 가지 길찾기

초기 화면은 `36.365473, 127.338021`을 중심으로 반경 1km의 샘플 구간을 표시합니다. 지도에서 출발과 도착을 차례로 선택하면 다음 세 기준을 비교합니다. 구간 중간에서도 점을 지정할 수 있습니다.

| 옵션 | 선택 기준 |
| --- | --- |
| 최단 거리 | 구간 길이의 합 최소화 |
| 최적 거리 | `길이 × (1 + 2 × 위험도/100)`의 합 최소화 |
| 안전 거리 | 우회 한도 `max(최단 × 1.5, 최단 + 80m)` 안에서 `길이 × (0.000001 + 위험도/100)`의 합 최소화 |

세 옵션은 수집된 연결망 안에서 탐색하므로 같은 경로를 고를 수도 있고, 최적 거리가 제3의 경로가 될 수도 있습니다. 통과 불가·미확인 구간과 설정한 휠체어 조건을 충족하지 않는 구간은 탐색에서 제외합니다. 경로를 선택하면 이동거리, 예상 시간, 평균 위험도와 최대 위험도를 표시합니다. `다시 두 점 찍기`는 경로를 지우고 두 점을 다시 선택하며, `초기화하기`는 전체 선택을 지웁니다.

카카오 도보 경로는 **경로 좌표**를 제공합니다. 인도 폭, 단차, 실측 안전도는 제공하지 않습니다. 대로변과 골목의 노면 등급 분포 및 정적·동적 위험도는 기능 시연용으로 생성한 값입니다. 초기 화면의 지역 샘플망은 수집 당시의 스냅샷이며 반경 1km의 모든 도보를 보장하지 않습니다. OSM 시연망을 선택할 수도 있으며 해당 데이터는 [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)의 ODbL 조건을 따릅니다.

## 로컬 실행

Node.js 22 이상이 필요합니다. 앱 런타임에는 외부 npm 의존성이 없습니다.

```bash
cd mvw-measured-map
cp .env.example .env
# .env의 KAKAO_REST_API_KEY 설정
npm start
```

`http://127.0.0.1:3000`으로 접속합니다. 카카오 JavaScript SDK 도메인에 로컬 주소를 등록하고, 화면의 **지도 연결**에서 JavaScript 키를 설정해야 카카오맵이 나타납니다. REST API 키는 서버의 `.env`에만 두고 저장소나 브라우저 코드에 넣지 않습니다. 키 없이도 포함된 정적 실측 데이터는 확인할 수 있지만, 실시간 카카오 도보 경로 요청에는 API 서버 설정이 필요합니다.

```bash
npm test
npm run build
```
